# 语言风格约束指南

## 概述

本指南为中文本科论文写作提供语言风格约束，确保 AI 生成的论文符合学术写作规范，避免常见的 AI 写作痕迹。

---

## 一、句式规范

### 1.1 主语规范

**优先使用的主语：**
- "本系统" / "本平台" / "本研究"
- "本文" / "本章" / "本节"
- "实验结果表明" / "测试结果显示"
- "表X数据说明" / "图X展示了"

**避免的主语：**
- ❌ "我们" / "笔者"（除非学校模板明确要求）
- ❌ 无主语句堆砌（如："进行了测试，发现了问题，提出了方案"）
- ❌ "人们" / "大家" 等泛指主语

**示例：**
```
❌ 我们对系统进行了功能测试。
✅ 本章对系统进行了功能测试。

❌ 通过实验，发现了性能瓶颈。
✅ 实验结果表明，系统存在性能瓶颈。
```

### 1.2 长句拆分原则

**规则：** 单句超过 60 字时，必须拆分或用分号重组。

**拆分策略：**
1. 找到句子的逻辑断点（转折、并列、因果）
2. 在断点处拆分，补充适当的连接词
3. 保持每句话只表达一个完整意思

**示例：**
```
❌ 本文提出了一种基于区块链的时间银行社区服务平台设计方案，该方案通过智能合约实现了时间币的自动发放和兑换功能，并且采用了去中心化的存储方式确保了数据的安全性和透明性。

✅ 本文提出了一种基于区块链的时间银行社区服务平台设计方案。该方案通过智能合约实现了时间币的自动发放和兑换功能。同时，采用去中心化存储方式确保了数据的安全性和透明性。
```

### 1.3 句式多样性

**避免的重复模式：**
- ❌ 连续两句以"通过……"开头
- ❌ 连续三句以相同词开头
- ❌ 连续使用"首先……其次……最后……"结构

**推荐的句式变化：**
- 使用"在此基础上" / "与此同时" / "进一步地" 等过渡
- 使用"如表X所示" / "由图X可知" 等引导
- 使用"值得注意的是" / "需要说明的是" 等插入语

## 二、词汇规范

### 2.1 学术术语规范

**维护 domain-vocab.yaml 文件，按论文类型分类：**

```yaml
# 软件工程类
software_engineering:
  correct:
    - "执行" / "实现" / "完成"
    - "优化" / "改进" / "提升"
    - "设计" / "构建" / "开发"
  incorrect:
    - "进行了……的操作"
    - "做了……的事情"
    - "搞了……的测试"

# 电子信息类
electronic_engineering:
  correct:
    - "测量" / "检测" / "采集"
    - "信号处理" / "数据处理"
    - "算法实现" / "功能实现"
  incorrect:
    - "测了……的数据"
    - "搞了……的信号"
```

### 2.2 禁用词表

**空泛套话（必须避免）：**
- ❌ "显著提升用户体验"
- ❌ "具有重要意义"
- ❌ "取得了良好效果"
- ❌ "具有广阔的应用前景"
- ❌ "为……奠定了基础"
- ❌ "提供了新的思路"
- ❌ "具有重要的理论价值"

**替换建议：**
```
❌ "显著提升了系统性能"
✅ "系统响应时间从 2.3s 降低至 0.8s，提升幅度达 65%"

❌ "具有重要的实际意义"
✅ "解决了社区服务中时间记录不透明、信任成本高的实际问题"
```

### 2.3 数字使用规范

**规则：**
- 一律使用阿拉伯数字（除成语、惯用语外）
- 百分比用 `%` 符号
- 时间用 24 小时制

**示例：**
```
❌ 百分之六十
✅ 60%

❌ 两千三百次
✅ 2300 次
```

## 三、段落结构规范

### 3.1 三段式结构

**每个正文段落必须包含：**
1. **论点句**：明确本段要说明什么
2. **证据/数据句**：提供具体的事实、数据、例子
3. **分析句**：解释证据说明了什么，得出什么结论

**示例：**
```
[论点句] 系统性能测试结果表明，本平台能够满足大规模并发访问需求。
[证据句] 在 1000 并发用户的测试场景下，系统平均响应时间为 0.8 秒，
         峰值响应时间为 1.2 秒，CPU 占用率稳定在 45% 以下。
[分析句] 这一结果表明，系统的并发处理能力和资源利用效率均达到预期目标，
         能够支撑社区级别的日常使用场景。
```

### 3.2 段落字数要求

**规则：**
- 正文段落字数不少于 80 字
- 不超过 300 字（过长需拆分）
- 每段只讨论一个主题

### 3.3 避免的段落类型

- ❌ 只有叙述没有分析的段落
- ❌ 只有观点没有证据的段落
- ❌ 大段罗列（超过 3 项应使用表格或列表）

## 四、专业术语规范

### 4.1 括号内英文标注

**规则：**
- 首次出现的专业术语，括号内需标注英文原文
- 格式：中文术语（English Term）
- 后续出现可省略英文

**示例：**
```
✅ 智能合约（Smart Contract）是一种自动执行的计算机程序。
✅ 区块链（Blockchain）技术具有去中心化特性。
   后续：智能合约通过预设规则自动执行交易。
```

### 4.2 缩写规范

**规则：**
- 首次使用需写全称，括号内标注缩写
- 格式：全称（缩写）
- 后续可直接使用缩写

**示例：**
```
✅ 去中心化自治组织（Decentralized Autonomous Organization, DAO）
   后续：DAO 的治理机制采用投票表决方式。
```

## 五、检查清单

在提交论文前，逐项检查：

- [ ] 主语是否符合规范（本系统/本文/实验结果表明）
- [ ] 是否有超过 60 字的长句
- [ ] 是否有连续相同句式开头
- [ ] 是否使用了禁用词表中的空泛表达
- [ ] 数字是否使用阿拉伯数字
- [ ] 每段是否包含论点、证据、分析三要素
- [ ] 段落字数是否在 80-300 字范围内
- [ ] 专业术语首次出现是否标注英文
- [ ] 缩写首次使用是否写全称

## 六、与现有工作流的集成

### 6.1 在 draft_chapters 中的应用

每章写完后，必须过一遍本指南的禁用词表和句式规范，不符合的段落必须修改。

### 6.2 在 quality_gates 中的应用

运行 `check_prose_quality.py` 脚本，自动检测本指南中的各项规范，生成检查报告。

### 6.3 与 AIGC 治理的关系

本指南侧重于语言表达规范，AIGC 治理侧重于内容真实性和原创性。两者相辅相成，共同确保论文质量。
